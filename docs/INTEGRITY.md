# Data Integrity Register

Nakshatra-X is a decision-support tool for a government problem statement
(SIH26009, Ministry of Steel / MOIL). Judges are entitled to ask, of any number
on screen, "where did that come from?" This document answers that for every
value the system displays, and records what was previously fabricated.

**The operating rule:** every displayed number comes from a real computation
over either real data or clearly-flagged synthetic data. Synthetic data is
expected — MOIL's operational data is proprietary — but it is never labelled
live.

## 1. The provenance envelope

Every value exposed through the API carries an envelope
(`frontend/src/lib/provenance.ts`):

```ts
{ value, unit, source, source_kind, vintage, model_version,
  uncertainty, is_synthetic, is_live, method }
```

`is_synthetic` and `is_live` are **computed from `source_kind`**, not passed in,
so a caller cannot mislabel synthetic data as live. The four kinds are:

| kind | meaning | `is_live` | `is_synthetic` |
|---|---|---|---|
| `measured` | fetched this request from a real external API | true | false |
| `derived` | computed deterministically from measured inputs | false | false |
| `synthetic` | produced by the seeded synthetic generator | false | true |
| `reference` | fixed constant (mine coordinates, lease targets) | false | false |

Responses also carry a `data_integrity` banner stating whether the payload
mixes sources, whether the live fetch succeeded, and the staleness of the
freshest measured input.

## 3. What is synthetic, and why

MOIL does not publish per-mine equipment availability, downtime, or blast
records. These are generated by `lib/synthetic.ts` using a seeded PRNG
(mulberry32) keyed on `mine | channel | operating-day`:

- values are **stable within an operating day** and **reproducible** for any
  given day, so a demo does not shimmer;
- there is **no `Math.random` on any data path**;
- scale is anchored to MOIL's public annual production totals — order of
  magnitude only, and labelled as such, never presented as MOIL's figures.

Currently synthetic: equipment downtime hours, equipment availability, weekly
blast counts, and — only when the upstream weather call fails — the weather
block.

Currently measured: rainfall (14-day, past days only), forecast rainfall,
temperature, humidity, soil moisture, all from Open-Meteo; and Sentinel-2
scene metadata from Earth Search STAC.

## 4. Known-invalid metric (not yet fixed)

The prospectivity model in `AI/` reports ~0.98 AUC. **This number is not
meaningful.** `KNOWN_FAULTS` in `AI/scripts/02_extract_features.py` is the list
of known mine coordinates, and the "spectral" features are computed as a
function of distance to those points — so the features encode the label. The
model is largely recovering its own target.

This is recorded here rather than quietly left in place. It is fixed in Phase 5
(real Sentinel-2 band ratios, DEM slope, leave-one-mine-out CV, honest AUC).
Until then the figure is withdrawn from the chatbot knowledge base and must not
be quoted.

## 5. Guardrails

1. **No subsurface ore detection from satellite.** Sentinel-2 is surface
   reflectance. Scene data is presented as surface/atmospheric context for
   prioritising where to look, never as evidence of ore at depth.
2. **No statutory reserve figures.** Output is decision support. The telemetry
   `audit` block carries this statement, and the `UNFC 111` labels have been
   removed from the response path.
3. **Constraints are enforced, not learned.** (Phase 4 constraint engine.)
4. **Degrade gracefully and state staleness.** `data_integrity` reports the
   degraded reason and the age of the freshest measured input.

## 6. How to verify

```bash
# No randomness on data paths
grep -rn "Math.random\|jitter(" frontend/src/app/api frontend/src/components/mission-control/data.ts

# No fabricated model names anywhere
grep -rn "Prophet-XGBoost\|TreeSHAP\|XGBoost-Manganese\|KernelExplainer" frontend/src backend AI

# Reproducibility: two identical requests, identical values
curl -s localhost:3000/api/v1/mines/1/telemetry -o a.json
curl -s localhost:3000/api/v1/mines/1/telemetry -o b.json
python3 -c "import json;a=json.load(open('a.json'));b=json.load(open('b.json'));print({k:v['value'] for k,v in a['provenance'].items()} == {k:v['value'] for k,v in b['provenance'].items()})"
```
